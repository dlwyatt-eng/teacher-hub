## Loading investigation and targeted repair

The Hub error boundary previously showed the same refresh/Wi-Fi/update explanation for any rendering exception. Fresh Mathematics loaded without that error during this investigation. The user's exact failed page and console error have not been supplied, so the cause is not confirmed. Vite documents missing old dynamic-import files after deployment as a known failure mode: https://vite.dev/guide/build#load-error-handling . This site rebuilds hashed files and previously replaced the whole Pages artifact, making stale tabs a plausible cause. An attempted web retrieval of an old asset was blocked by the retrieval tool; it was not a verified 404.

The error boundary now distinguishes recognized module/CSS download errors from ordinary render errors. Its manual refresh requests a cache-busting URL while preserving the current route and hash. There is no automatic reload loop or storage clearing. A note warns users to copy unfinished text before refreshing.

Deployment now restores an asset-history cache, retains up to two preceding successful generations of hashed assets, and keeps the newly tested HTML/source authoritative. The cache is saved only after successful deployment. No old index.html is restored and current files cannot be overwritten. The first release seeds the cache; already-stale tabs may still need one refresh. Cache eviction or tabs older than the retention window can still need refresh. For an urgent removal of public code, invalidate the pages-assets-v1 cache prefix and deploy cleanly rather than retaining the removed assets.
